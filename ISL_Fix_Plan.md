# ISLTranslate repo: fix plan for the implementation agent

Repo: `https://github.com/balu-16/ISLTranslate` · base commit `7b583417611493c99400c935327ea3b8bafbda1f`
Work on branch `fix/review-2026-10` and open one PR. **Make one commit per task ID** (e.g. `P0-1: fix gold CSV aliases`) so each fix can be reviewed alone.

## Ground rules (do not break these)
- Keep the scientific design: whole-source-video holdout, gold parents fully held out, strict pretraining exclusion, leakage assert before train/eval, CE-only baseline, BoW as the only default auxiliary loss, no CTC, T/2 default with T/4 option, visual-only prediction (no references reach the model), token-normalised accumulation.
- Do **not** start training, download the 170 GB iSign poses, or use paid GPU. Small downloads (CSV files, Flan-T5-small, a single sample pose file) are allowed.
- Work through the tasks in order: **P0 → P1 → P2 → P3**. Do not start a later group until the earlier one is done.
- Every task ends with the listed acceptance check. Add a unit test for it under `tests/` (pytest, CPU-only, synthetic data, under 60 s total).
- Update the docs, configs, the notebook and the runbook in the same commit as the code they describe.
- If a task is ambiguous or blocked after 2 attempts, stop and write the question in `docs/open_questions.md`. Don't guess.

## Verified facts about the real data (checked Oct 21, 2026)
- `data/ISLTranslate.csv` (Exploration-Lab/ISLTranslate, main): header `uid,text`. It has 31,222 rows but only 31,221 unique UIDs, because `UbhONRGm-90--61` appears twice with identical text. Many texts have a leading space.
- UID patterns:
  - Sentence clips: `<parent>-<n>`, matched by `^(?P<source>.+)-(?P<sequence>\d+)$`. These cover 210 parents. The parent can itself end in `-` (e.g. `dJ_5m1Y2InE-`), which is fine as long as grouping is consistent.
  - Dictionary (DEF) clips: `<11-char YouTube ID>_<tag>` with tag `w`, `d`, `e1`–`e5`. There are 2,691 rows from 586 videos, matched by `^(?P<source>[A-Za-z0-9_-]{11})_(?P<tag>(?:w|d|e\d+))$`. The current regex does **not** match them.
- `data/ISL-signer_validation.csv` (gold, 291 rows): its headers are exactly
  `uid`, `Transcribed Text (text present in iSign/ISLTranslate translation dataset)`, `Gold Translation (text generated by ISL Singer)`.
  All 291 UIDs exist in ISLTranslate.csv. They come from 4 parents, and those parents hold **397** clips in total.

## P0: crashes before training (must fix first)

### P0-1 Gold CSV column aliases
- **Problem:** `config.py` (`Data.interpreter_columns`) and `configs/baseline.yaml` alias `Transcribed Text` / `Gold Translation`. `manifests.mapped_columns` needs an exact match, so `audit` raises on the public file.
- **Fix:** In both places, add the full header strings as aliases and keep the short ones as well. `mapped_columns` must still demand exactly one match.
- **Accept:** a test builds a 3-row CSV with the real headers and checks that `attach_interpreter` fills `interpreter_text` and `interpreter_transcript`.

### P0-2 Duplicate UID handling
- **Problem:** `make_splits` aborts on `duplicate_uids` (`UbhONRGm-90--61`).
- **Fix:** In `adapt_csv`, collapse rows that are exact duplicates (same uid **and** same stripped text) into one, and record each collapse in the audit report under `collapsed_exact_duplicates`. If the same UID appears with *different* text, still raise.
- **Accept:** a test where an identical duplicate becomes 1 record and a conflicting duplicate raises `ValueError`.

### P0-3 Source-mapping generator (both UID patterns)
- **Problem:** The default protocol `source-held-out` requires every record to have `source_verified=true` from `data/metadata/source_mapping.csv`, and nothing in the repo creates that file. The DEF UIDs don't match the default regex at all.
- **Fix:**
  1. Change `Adapter.candidate_uid_pattern: str` to `candidate_uid_patterns: list[str]` and try each pattern in order. The defaults are the two regexes above. Update every config that uses it.
  2. Add a CLI command `make-source-map --config X [--out path]`. It reads the annotation CSV(s) and writes `uid,source_id,verified,provenance`, with `verified=true` and `provenance=uid-structure:<pattern-name>` (pattern names: `sentence-suffix`, `def-tag`). Any UID that matches no pattern gets `verified=false, provenance=unresolved`. The command exits non-zero and lists those UIDs.
  3. Document in `docs/data_contracts.md` that "verified" here means *grouped by the dataset's UID convention (YouTube video ID)*, not manually checked.
- **Accept:** a test with sample UIDs (`1782bea75c7d-1`, `UbhONRGm-90--61`, `0EaLX2t1wPU_e1`, `0EaLX2t1wPU_w`, `garbage`). The first two must group under their parents, both DEF UIDs under `0EaLX2t1wPU`, and `garbage` must be reported unresolved.

### P0-4 GPU determinism crash
- **Problem:** `utils/runtime.seed_everything` calls `torch.use_deterministic_algorithms(True)` without `CUBLAS_WORKSPACE_CONFIG`, so PyTorch raises on the first cuBLAS matmul.
- **Fix:** Before enabling determinism, run `os.environ.setdefault("CUBLAS_WORKSPACE_CONFIG", ":4096:8")`. Call `torch.use_deterministic_algorithms(deterministic, warn_only=True)`. Log any op that warns, and add `CUBLAS_WORKSPACE_CONFIG=:4096:8` to `.env.example`.
- **Accept:** a test checks that the env var is set after `seed_everything(…, True)`. `env-check` reports the determinism mode.

### P0-5 Colab/Kaggle install and lockfile
- **Problem:** There is no `uv.lock`, so `uv sync --locked` fails. `notebooks/run_pipeline.ipynb` raises unless the kernel is the repo's `.venv`, so it can't run on Colab or Kaggle.
- **Fix:**
  1. Generate and commit `uv.lock` (`uv lock`).
  2. Add `requirements-colab.txt`, pinned to match the lock and leaving torch out (use Colab's own torch).
  3. Notebook: replace the hard `.venv` check with a mode switch: `RUNNER = "uv"` (local/AMD) or `"pip"` (Colab/Kaggle, calls `python -m isl_slt`). Add a first cell that clones the repo and runs `pip install -e . -r requirements-colab.txt` when `RUNNER == "pip"`.
  4. Add `docs/colab.md` with Drive-mounted paths for `data/`, `artifacts/` and `runs/`.
- **Accept:** `uv sync --locked --extra cpu` succeeds. In pip mode, the notebook's config cell runs in a fresh `python -m venv` without `.venv` existing.

### P0-6 Pose data acquisition and naming check
- **Problem:** Nothing downloads or extracts the iSign pose archive (HF dataset `Exploration-Lab/iSign`, gated, 4 parts), and the `{uid}.pose` naming is assumed.
- **Fix:**
  1. Add `scripts/fetch_isign.py`. It uses `huggingface_hub` with `HF_TOKEN` from the env to list the files in the dataset repo and print their names and sizes, and downloads the CSV(s) only. It has a `--parts` flag for later full download. Implement the extraction as **streaming**: extract only the members whose UID is in a given manifest, so the full archive never has to sit on disk unpacked.
  2. Add `scripts/inspect_pose.py <file.pose>`, which prints the header components, point names, fps, width/height and frame count, and checks that the joint names in `features/pose.py` (`POSE_LANDMARKS`, `LEFT_HAND_LANDMARKS`, `RIGHT_HAND_LANDMARKS`, and `FACE_LANDMARKS` if the face is present) exist.
  3. Make `pose_pattern` and component names configurable if the real files differ. Record the real layout in `docs/data_contracts.md`.
- **Accept:** running `fetch_isign.py --list` prints the repo file listing (needs only a token). `inspect_pose.py` works on a synthetic pose-format file in tests.

## P1: result validity

### P1-1 Paired gold scoring (other review's R3)
- **Problem:** `evaluation/generation.score_rows` scores transcript refs over all 397 gold-partition clips but interpreter refs over only the 291 annotated ones.
- **Fix:** Whenever gold rows exist, also report `transcript_on_gold_subset`: the same predictions scored against the transcript on exactly the 291 rows. Assert that both reports share the same UID list (store its count and hash).
- **Accept:** a test with 5 rows, 3 of them annotated, checks that both subset reports have count 3 and the same UID hash.

### P1-2 Effective-evaluation fingerprint (R7)
- **Problem:** `workflows.comparison_fingerprint` uses `predictor.config.generation` from the checkpoint, not the `config.generation` actually used for evaluation, so `aggregate_runs` can merge incomparable runs.
- **Fix:** Fingerprint the effective evaluation config (generation settings, selected beams, metric list, normalisation, metric signatures). Make `aggregate_runs` reject any mismatch.
- **Accept:** a test where two reports that differ only in `max_new_tokens` are rejected by `summarize`.

### P1-3 Lowercased and cased metrics
- **Fix:** In `metrics.score_predictions`, also report BLEU-1..4 and chrF++ with `lowercase=True` under `*_lc` keys, so results can be compared with the ISLTranslate paper's baseline. Keep cased BLEU as the primary score.
- **Accept:** a test where "Hello world" vs "hello world" gives `bleu4_lc` = 100 and `bleu4` < 100.

### P1-4 Feature standardisation
- **Problem:** Velocity is in units per second (about 25× the position scale), and half of the 384 input dims are 0/1 masks. Nothing is standardised.
- **Fix:**
  1. Change velocity to a per-frame difference (multiply by the median frame interval), or add a config flag `velocity_units: per_frame | per_second` defaulting to `per_frame`.
  2. Add `prepare-stats`: compute the mean and std of the continuous channels **on the train split only** over valid frames, save them with a hash, and apply them in the model input (masks stay 0/1). Store the stats hash in checkpoint compatibility.
- **Accept:** a test checks that the stats are computed from train records only (a validation record with huge values doesn't change them) and that masks are untouched.

### P1-5 Velocity as an ablation (v7 Baseline A = body + hand positions)
- **Fix:** Add `features.velocity: bool` (default `false` for `baseline.yaml`) and a new `configs/velocity.yaml` that sets it to `true`. Include it in `preprocessing_fingerprint`.
- **Accept:** a test where the input dim changes by 96 when velocity is toggled on the 48-joint baseline.

### P1-6 Overfit preset (A3)
- **Fix:** Add `configs/overfit.yaml`: dropout 0, weight_decay 0, pose_noise 0, no lexical, one stage with T5 unfrozen, patience large, `beams: [1]`. Update the runbook. Don't add a BLEU assertion.
- **Accept:** the config loads and `plan --config configs/overfit.yaml` prints dropout 0.

### P1-7 Checkpoint selection policy (A5)
- **Fix:** Keep `best-bleu.pt` and `best-chrf.pt`. Add `best-guarded.pt`, saved only when BLEU-4 improves and chrF++ doesn't drop by more than 0.5. Document all three in `docs/architecture.md`.
- **Accept:** a unit test of the guard function.

## P2: speed and cost

### P2-1 Stop re-hashing raw poses every run
- **Problem:** The `PoseDataset` preflight calls `read_features(verify_assets=True)`, which runs `record_signature` and SHA-256s every raw `.pose` file on every dataset build. That rereads 170 GB for pretraining, and the raw poses can never be deleted after caching.
- **Fix:** Verify raw assets only in `prepare-features` and in an explicit `verify-cache` command. Training and evaluation should check the cache's own metadata (preprocessing fingerprint, record key, stored dependency signatures) without opening the raw files. Add `--verify-assets` to opt in.
- **Accept:** a test where training-dataset construction succeeds after the raw pose file is deleted, and `verify-cache` then fails clearly.

### P2-2 Remove the per-item cache hash and enable workers
- **Fix:** In `__getitem__`, skip the npz SHA-256 (it's already verified once in the preflight). Set the default `data.workers: 4` with `persistent_workers=True` and `pin_memory` on GPU. Make sure the `Collator` and records pickle cleanly.
- **Accept:** a test that a DataLoader with `num_workers=2` iterates over a synthetic dataset.

### P2-3 Cheaper per-epoch validation
- **Fix:** Add `generation.train_beams: [1]` for per-epoch validation. Run the full `generation.beams` sweep only in the final `evaluate --partition validation`.
- **Accept:** the engine uses `train_beams` (unit test with a mocked generator).

### P2-4 Context dependency scaling (R6)
- **Fix:** Pre-index records by `(source_id, split)` once (a dict), and memoise each record's signature per process. Hash each source once per command, not once per clip.
- **Accept:** a test with 1 source × 200 clips counts `file_hash` calls ≤ 200 + a small constant.

### P2-5 Smaller checkpoints
- **Fix:** Only `last.pt` keeps optimizer, scheduler, scaler and RNG state. The best checkpoints and the `epoch-*` files store weights + config + tokenizer only. Add a size column to the run summary.
- **Accept:** a test where a best-checkpoint payload has no `optimizer` key and loads for inference.

## P3: hardening

### P3-1 Test suite (R1)
Make sure `tests/` covers at least these:
- Conv output lengths and masks for T/2 and T/4 at odd lengths, and padding invariance (padding a batch doesn't change a sample's outputs).
- Gradients reach `visual.*` when T5 is frozen.
- Accumulation: the loss over 2 micro-batches equals the loss over one merged batch (same token count).
- Leakage assert: it fails on a shared source across train and test, and on a pretrain row whose parent is held out.
- Splits are deterministic for a fixed seed, and gold parents always land in `gold`.
- Generation never receives labels (mock the T5 and assert that `labels` is absent from the `generate` kwargs).
- Resume: train 2 windows, save, resume, and check that state and parameters match an uninterrupted run (CPU, tiny model).
- Diagnostics: blank keeps the length, shuffle permutes, and the swap donor differs.
Add `pytest` to a `dev` extra and a `make test` / `uv run pytest` line to the README.

### P3-2 Rename "original-paper" protocol (R4)
- Rename it to `external-membership-gold-safe`, make its exported `algorithm` metadata say `external-membership`, and document that a true paper reproduction isn't possible because no public UID membership exists.

### P3-3 Averaged checkpoints usable everywhere (R5)
- Add one `load_decoding_selection(path, checkpoint_sha, validation_hash, generation_hash)` helper. Add `--decoding` to `predict`, `benchmark` and `diagnostics`, and use the helper in all of them plus `evaluate`.

### P3-4 Resume binds code and environment (R8)
- Store the git commit, a dirty flag and a hash of `src/` in the checkpoint compatibility data. On resume, refuse a mismatch unless `--allow-code-change` is given, and log it when it is.

### P3-5 Training logs (A4)
- Each update event records the learning rate per group, update wall time, examples/sec and frames/sec, and peak GPU memory. Each epoch event records train seconds and validation seconds separately. Add `scripts/summarize_run.py` to print these numbers for the `estimate` command.

### P3-6 Small docs items
- A1: document the RGB hand-slot masking policy. A7: either wire `evaluation.repeat_seeds` and `bootstrap_samples` into the CLI defaults or state that they're unused. A8: document that pose noise is feature-space only.
- Update `docs/implementation_status.md` to list what this PR fixed and what is still unverified.
